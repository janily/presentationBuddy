# Reliability, experience and performance audit

## Goal
Preserve the existing brief → outline review → generated HTML product while making its boundaries trustworthy. Success means accepted user choices survive the API boundary, generated code cannot control the studio, cancelled work cannot publish late updates, and deterministic regression tests plus production compilation pass.

## Scope and decisions
- Fix reproducible defects in the existing Next.js/Mastra architecture; do not rewrite the product or replace model providers.
- Work only on `fix/reliability-performance-audit-20260924`; never merge or deploy production in this audit.
- Compare the synchronized npm lockfile with the stale pnpm lock before selecting one canonical install path. Do not silently install unpinned dependency trees.
- No real model API keys, paid generation or production customer content are used in validation.
- Treat source validation as a structural heuristic, not a guarantee of rendered design quality.

## Execution sequence
1. Reproduce clean installation, unit tests, lint, type checking and production build. Record baseline failures separately.
2. Write failing route tests for lost generation options and malformed JSON; preserve the validated input and return a client error for malformed input.
3. Write failing preview tests: opaque iframe origin, standalone/static response sandbox, input validation and correct file error statuses. Preserve inline navigation and parent-controlled HTML download.
4. Write failing skill-loader tests for traversal and concurrent repeated reads; resolve only trusted bundled paths, cache successful immutable reads and evict failed reads.
5. Write failing cancellation/resource tests. Ignore events after cancellation and clear timeout handles after each completed stream operation.
6. Remove repeated whole-history flattening; test newest run precedence and suspended outline lookup independently of object insertion order.
7. Preserve the preview browsing context while a revision starts/stops and improve the small-screen workspace. Verify in a browser where execution is available.
8. Re-run the complete suite, lint, types and production build. Perform a separate author self-review, record outstanding risks, and publish branch changes plus an auditable report.

## Review focus
- New start vs resume vs revision must keep existing wire contracts.
- Missing/aborted streams must not leak readers, timers, or uncaught cancellation promises.
- Direct generated-file URLs must be isolated as well as embedded previews.
- Unsafe style metadata must not read files outside the bundled skill.
- In-memory workflow/artifact/proposal state is not durable or distributed consistency; this remains an explicit deployment limitation unless independently addressed and tested.
